# Maintaining The Joinery

How the site is organised, and how to change it. For what the site is, see [README.md](README.md).

## Folder guide

| Path | What it is |
| --- | --- |
| `index.html` | The page that loads everything. Also holds the logo (inline SVG, also the favicon) and the link-preview tags |
| `css/styles.css` | All styling. The colours for light and dark live in the variables at the top |
| `js/app.js` | The pages and navigation (a hash router: `#/home`, `#/lab`, `#/glossary`, ...) |
| `js/db.js` | Runs SQL in the browser and checks answers |
| `js/progress.js` | Saves progress in the browser, including the review schedule |
| `js/hints.js` | Turns wrong answers and SQL errors into plain-language advice |
| `js/translate.js` | The "Translate to another database" rules used in the SQL lab |
| `js/byte.js` | Byte the beetle |
| `js/network.js` | The animated network on the home page |
| `js/markdown.js` | Shows each project's `PROJECT.md` as a page |
| `js/glossary-visuals.js` | The small diagrams on some glossary terms |
| `js/analytics.js` | GoatCounter visit counts (only on thejoinery.dev) |
| `data/exercises.js` | The SQL exercises |
| `data/seed.js` | The SQL lab's practice database |
| `data/aloud.js` | Model explanations for "Explain it out loud" |
| `data/dialect-notes.js` | The side-by-side dialect comparison on the "SQL dialect" glossary term |
| `data/glossary.js`, `data/glossary-<area>.js` | The glossary: the list of areas, then one file per area |
| `data/routes.js` | The routes on the home page (New to data, Fill my gaps, and so on) |
| `data/pages.js` | About, Privacy, Contact and Roadmap, plus the contact email and portfolio link |
| `data/projects.js` | The Projects page list. Generated by the project build scripts: don't edit by hand |
| `projects/<id>/` | One folder per project or Python guide |
| `vendor/` | Third-party libraries and fonts, stored locally so the site works offline |

Progress is stored in the browser's localStorage under `data-learning-site-v1`, and settings under `data-learning-settings`. Saved progress files use the app id `data-learning-site`, so older exports keep importing.

## Common changes

### Add or change a SQL exercise
Edit `data/exercises.js`. Each exercise has a task, a hint, a model answer (`solution`) and an explanation. Answers are checked by running the learner's query and the model answer against a fresh copy of the database and comparing the results.

### Add a glossary term
Copy a block in the right `data/glossary-<area>.js` file and give it a new `id`. `data/glossary.js` explains every field. The `rel` list may only use ids that exist. To give a term a diagram, add a function with the same id to `js/glossary-visuals.js`.

### Add a glossary area
Add the area to the list in `data/glossary.js`, create `data/glossary-<area>.js`, add its `<script>` tag to `index.html`, give it a quiz name in `QUIZ_AREA` in `js/app.js`, and give it an accent colour in `css/styles.css` (`[data-area="..."]`).

### Change a route
Edit `data/routes.js`. Each route has a name, a description, a headline, a list of steps (each with a link) and an optional note.

### Change the About, Privacy, Contact or Roadmap pages
Edit `data/pages.js`. The contact email, portfolio link and "last updated" date are in `window.SITE` at the top.

## Projects

Each project is a folder in `projects/<id>/` with a `meta.json` (title, blurb, brief, step titles), a `PROJECT.md` (the full write-up; every `## 1. ...` heading becomes a step with a tick box) and any downloads. `data/projects.js` is built from the `meta.json` files, sorted by `order`.

The sources live outside the site folder, in `project-sources/`, and stay off GitHub because they reveal the patterns learners are meant to discover.

- **Just Now Deliveries** (`project-sources/just-now-deliveries/`): `generate.py` makes the data (seeded, so it is always the same), `solution/` holds the model scripts, and `build_project.py` runs everything and rebuilds the zips, charts and `data/projects.js` from the real results.
- **Build the plumbing** (`project-sources/build-the-plumbing/`): built the same way, with its own `build_project.py`.

To change a project: edit the source, run its `build_project.py`, then commit the changed site files.

## Python practice

Short guides that run in Google Colab, listed under "Python practice" on the Projects page. Any project whose `meta.json` has `"track": "Python"` appears there instead of as a card, sorted by `order` (10 onwards).

- `projects/python-basics/`: guide 1, read and clean a messy CSV.
- `projects/python-explore`, `python-merge`, `python-dates`, `python-charts`, `python-duckdb`, `python-files`: guides 2 to 7, each with a `PROJECT.md`, a Colab notebook (`<id>.ipynb`), `meta.json` and, for charts, the pictures.
- `projects/python-data/`: the shared practice data the guides read from the site.

The guides read files from thejoinery.dev with `storage_options=headers` (a browser-style User-Agent), because Cloudflare turns away Python's default one with a 403 error.

The sources are in `project-sources/python-basics/`:

1. `python make_python_data.py` makes the shared practice data.
2. `python run_guides.py` runs every step of every guide for real and records the outputs and charts. Add `--check --live` to test against the live site without saving anything.
3. `python build_guides.py` writes each guide's page, notebook and `meta.json`.

Guide 1 has its own `make_practice_csv.py`, `steps.py` and `build_guide.py`. To change a guide, edit `guides/<id>.md` (the text) or `guides/<id>.py` (the code), then run steps 2 and 3.

## Hosting

The site is static. The repository is `danikabuilds/the-joinery` on GitHub, and Cloudflare Pages publishes every commit to `main` at thejoinery.dev, usually within a minute. GitHub Pages stays switched on so that the old address, danikabuilds.github.io/the-joinery, forwards to the new one. `.nojekyll` stops GitHub Pages from misreading the dbt files.
